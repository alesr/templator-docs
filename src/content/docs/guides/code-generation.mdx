---
title: Generate typed accessors
description: Replace reg.Get string lookups with generated methods like tpl.GetComponentsHeader using cmd/generate and go:generate.
---

`reg.Get("components/header")` is a stringly-typed API inside an otherwise
type-safe flow: rename a file and the compiler stays silent. The accessor
generator closes that gap. It scans your templates directory and emits a
typed wrapper — one method per template:

```go
home, err := tpl.GetHome()           // templates/home.html
header, err := tpl.GetComponentsHeader() // templates/components/header.html
```

The generated code calls `registry.Get` under the hood, so behavior is
identical — this is purely developer ergonomics plus refactor safety.

## Run the generator

```sh
go run github.com/alesr/templator/cmd/generate \
  -package main \
  -templates ./templates \
  -out ./templator_accessors_gen.go
```

Or install it once and run as a command:

```sh
go install github.com/alesr/templator/cmd/generate@latest
```

All flags and defaults are in the [Generator CLI](/templator-docs/reference/generator/)
reference.

## What it generates

Given:

```text
templates/
  home.html
  about.html
  components/header.html
```

the generator writes `templator_accessors_gen.go`:

```go
// Code generated by go generate; DO NOT EDIT.
package main

import "github.com/alesr/templator"

// TemplateAccessors provides typed helper accessors over templator Registry.
type TemplateAccessors[T any] struct {
	registry *templator.Registry[T]
}

// NewTemplateAccessors creates a TemplateAccessors wrapper for a templator Registry.
func NewTemplateAccessors[T any](registry *templator.Registry[T]) *TemplateAccessors[T] {
	return &TemplateAccessors[T]{registry: registry}
}

// GetHome returns a handler for the home template.
func (r *TemplateAccessors[T]) GetHome() (*templator.Handler[T], error) {
	return r.registry.Get("home")
}

// GetAbout returns a handler for the about template.
func (r *TemplateAccessors[T]) GetAbout() (*templator.Handler[T], error) {
	return r.registry.Get("about")
}

// GetComponentsHeader returns a handler for the components/header template.
func (r *TemplateAccessors[T]) GetComponentsHeader() (*templator.Handler[T], error) {
	return r.registry.Get("components/header")
}
```

Naming rule: each path segment is title-cased (English casing, via
`golang.org/x/text/cases`) and the segments are joined after `Get`. The
template name keeps its slash-separated form (`components/header`), which is
exactly what `Registry.Get` expects ([Registry and
handlers](/templator-docs/concepts/registry-and-handlers/)). The output
is gofmt-formatted.

## Wire it into go:generate

Add the directive to one of your source files so regeneration is one command:

```go
//go:generate go run github.com/alesr/templator/cmd/generate -package main -templates ./templates -out ./templator_accessors_gen.go
```

```sh
go generate ./...
```

## Use the accessors

```go
fs := os.DirFS(".")
reg, _ := templator.NewRegistry[HomeData](fs)

tpl := NewTemplateAccessors(reg)

home, err := tpl.GetHome()
if err != nil {
	log.Fatal(err)
}

// home is *templator.Handler[HomeData] — same full behavior:
err = home.Execute(ctx, w, HomeData{Title: "Welcome"})
```

`TemplateAccessors[T]` keeps the generic type parameter, so it works with
any registry without boxing handlers away from the type-safe `Handler[T]`
API.

## Regeneration habits

- **Commit the generated file** — it is small, reviewable, and keeps builds
  hermetic.
- **Regenerate on template inventory changes**: adding, removing, or
  renaming a template requires a `go generate ./...` pass. If you forget,
  the build fails on stale or missing methods (`GetAbout` used without
  existing) — which is the same discipline as any `_gen.go` file.
- **Never hand-edit**: the file is gofmt'd, deterministic, and `DO NOT
  EDIT`-marked for a reason; change the templates and regenerate instead.

:::note
A stale generation is a compile error, not a silent failure — deleting
`templates/about.html` leaves `GetAbout` until you regenerate, at which
point it is removed and any lingering call site breaks the build, while a
removed call for a still-existing template fails only at `Get` runtime.
This is the same failure shape as `reg.Get` with string names, but the
common refactors (renames, moves) are caught earlier.
:::
